# BioArt Studio 과학 도해 편집기 확장 계획

작성일: 2026-10-14 · 상태: 구현 전 검토안 · 조사 기준: 현재 저장소 코드와 LabCanvas 공개 문서

## 1. 제안

BioArt 제작실을 **클립아트 검색·조립 도구에서 자유롭게 그리고 수정할 수 있는 과학 도해 편집기로 확장한다.** 사용자는 AI 연결 없이 빈 캔버스에서 시작하고, BioArt 그림과 직접 그린 도형을 함께 편집하며, 필요할 때 AI에게 선택 영역의 수정을 맡길 수 있어야 한다.

LabCanvas에서 가장 먼저 가져올 가치는 자유로운 벡터 편집, 매개변수로 조절하는 과학 객체, 재편집 가능한 작업 흐름이다. 이를 먼저 완성하고, 같은 문서 안에 그래프·단백질·3D 결과를 넣으며, 슬라이드·포스터로 확장한다. LabCanvas 전체 제품군과 동등한 수준은 장기 목표로 삼는다.

권장 방향은 **기존 Electrobun·Python 백엔드·BioArt 카탈로그를 유지하고, 제작실의 문서 모델과 편집 화면을 교체**하는 것이다. 라이브러리 탐색까지 전면 재작성할 필요는 없다.

이 문서는 기능 구현을 시작하지 않은 계획서다. 기존 `IMPLEMENTATION_PLAN.md`는 초기 라이브러리 계획으로 보존하며, 제작실 확장은 이 문서를 기준으로 검토한다. 아래 성능·일정·기능 수는 목표 또는 추정이며 측정 결과가 아니다.

## 2. 조사 근거와 확인 범위

- LabCanvas 홈페이지, 기능 소개, 공식 사용 문서를 확인했다. 실제 Figure editor 주소도 브라우저로 열었으나 로그인 화면이 나타났다. 로그인 후 도구의 동작, 내보내기 품질, 속도는 직접 검증하지 않았다.
- 아래 LabCanvas 항목은 공식 문서에 설명된 제공 기능이다. 문구나 화면을 그대로 복제하는 것이 아니라 작업 능력을 참고해 독립적으로 구현한다.
- 현재 앱은 저장소 코드로 확인했다. 이번 계획 작성에서는 설치된 앱을 실행하거나 기존 테스트를 재실행하지 않았다.
- 라이브러리 후보는 Context7의 Fabric.js·Paper.js 문서로 기능을 확인했다. 실제 BioArt SVG 및 WKWebView 호환성은 0단계에서 검증한다.

## 4. LabCanvas 기능과 대응 범위

공식 문서상 Figure editor는 경로 편집, 도형 결합, 마스크, 정렬, 과학 브러시·객체, 수식·표를 제공한다. 별도 앱으로 슬라이드·포스터·분자·3D·단백질·그래프·광학·픽셀 편집이 소개되어 있다. [공식 기능 소개](https://www.labcanvas.com/features)

| 색·외형 | 그라디언트·스포이트 | 채움·선·불투명도·팔레트·스타일 복사 | 1–2 |

## 5. 사용자 경험과 화면 구성

### 5.1 작업의 중심

주요 사용자와 사용 맥락은 이번 요청의 scientific diagram 제작을 기준으로 연구자·논문 작성자·교육자료 제작자로 가정한다. 브랜드 취향은 새로 확정하지 않고, 기존 앱의 차분한 배경과 청록색 액션을 잠정 유지한다. 도구의 정보 밀도와 색·서체의 최종 결정은 실제 편집 시제품에서 검토한다.

가장 중요한 행동은 **원하는 과학적 관계를 그리고, 각 요소를 직접 고치며, 출처와 편집성을 유지한 파일로 저장하는 것**이다.

권장 화면 배치:

```text
프로젝트명 · 저장 상태      Undo/Redo · 보기/크기      내보내기
────────────────────────────────────────────────────────────
도구  자료 / 레이어       캔버스 + 아트보드         선택 속성
      검색·클립아트      확대·이동·선택·드로잉      위치·외형
      생성기·템플릿                              연결·출처
────────────────────────────────────────────────────────────
페이지/패널 · 확대율 · 단위               AI 대화 열기
```

- **좌측 도구:** 선택, 직접 선택, 손, 도형, 선/연결선, 펜, 연필, 과학 브러시, 텍스트.
- **자료 패널:** 제작실 안에서 BioArt 검색·추가. 트레이를 거쳐 나갔다 들어올 필요를 없앤다. 레이어 탭과 전환한다.
- **중앙:** 캔버스가 공간을 가장 많이 차지한다. 선택하지 않았을 때는 아트보드 속성, 선택했을 때는 해당 요소의 속성을 보여준다.
- **우측:** 도구와 선택에 맞는 속성. AI는 접을 수 있는 탭/드로어로 두어 항상 캔버스를 좁히지 않도록 한다.
- **작은 창:** 좌우 패널을 접고 하나씩 열 수 있게 한다. 1280×800과 1440×900에서 필수 작업이 가능한지 검증한다.
- **키보드:** 선택·이동·복제·그룹·실행 취소 지원. 텍스트 입력 중 단축키가 그림을 삭제하거나 전역 검색을 여는 충돌을 방지한다.
- **접근성:** 레이어 목록과 수치 속성으로 포인터 없이도 기본 편집이 가능해야 한다. 포커스·도구명·저장 상태를 보조 기술에 제공한다.

### 5.2 대표 작업 흐름

1. **빈 도해 → BioArt 검색 → 드래그 배치 → 도형·라벨·연결선 추가 → 정렬 → 내보내기.** Codex 로그인 없이 완료 가능해야 한다.
2. **원본 SVG 배치 → 편집용 복사본 만들기 → 특정 경로 색 변경 → 그룹화 → 원본 출처 확인.** 경로가 자동으로 생물학적 의미를 갖는다고 가정하지 않는다.
3. **곡선 그리기 → 세포막 브러시 적용 → 두께·간격 수정 → 수용체·화살표 추가.** 브러시와 경로는 다시 편집 가능해야 한다.
4. **요소 선택 → AI에 “간격을 맞추고 화살표를 곡선으로 바꿔줘” → 변경 미리보기 → 적용 → 한 번에 되돌리기.** 나머지 노드를 재생성하지 않는다.
5. **여러 패널 완성 → 174 mm, 600 dpi 지정 → 글자·래스터 해상도 검사 → SVG/PDF/TIFF 및 프로젝트 저장.** 특정 저널 적합성은 사용자가 요구사항을 지정했을 때만 판단한다.

### 5.3 필수 상태와 안내

| 상태 | 화면 반응 |
| --- | --- |
| 빈 프로젝트 | 빈 캔버스·자료 추가·템플릿 시작; AI를 필수 절차로 만들지 않음 |
| 불러오는 중 | 문서/자료 로딩 표시, 편집 가능한 시점 구분 |
| 자료 누락 | 자리표시자와 파일 재연결; 전체 문서는 열 수 있음 |
| 다중 선택 | 공통 속성만 표시; 값이 다르면 혼합 상태 표시 |
| 저장 중/완료/실패 | 각각 구분; 실패 시 미저장 편집을 유지하고 재시도 |
| 충돌 | 최신 문서와 내 변경을 보존; 조용히 덮어쓰기 금지 |
| SVG 부분 지원 | 원본 배치 유지 또는 지원 요소만 복사하는 선택 제공 |
| AI 작업 중/실패 | 일반 편집 유지; 결과 적용 시 revision 확인, 실패 시 기존 그림 유지 |
| 내보내기 문제 | 누락 파일, 잘리는 요소, 부족한 해상도를 구체적으로 표시 |

문구 예: “모든 변경 사항 저장됨”, “저장하지 못했습니다. 편집 내용은 복구본에 보관했습니다.”, “이 SVG의 일부 효과는 경로 편집으로 가져올 수 없습니다.” 마지막 두 문구는 실제 보존·검사가 완료된 경우에만 표시한다.

## 6. 편집 엔진과 문서 구조

### 6.1 권장 기술 선택

**Fabric.js를 상호작용 렌더러 후보로 채택하고, BioArt 고유 문서 모델을 정본으로 둔다.** Fabric은 텍스트 편집, 객체 변환, 그룹, 확대·이동, SVG 파싱을 제공한다. 출처·과학 객체·revision 같은 앱 데이터는 Fabric 객체 JSON에 종속시키지 않는다. [Fabric 공식 소개](https://fabricjs.com/), [사용자 속성 문서](https://fabricjs.com/docs/using-custom-properties)

| 선택지 | 평가 | 결정 |
| --- | --- | --- |
| Fabric 기반 편집 + 독립 문서 | 기본 직접 조작을 재사용하고 과학 기능에 집중 가능 | 0단계의 우선 검증안 |
| SVG DOM 기반 자체 편집 | SVG 표현 제어에 유리하나 선택·텍스트·변환 구현량 큼 | Fabric 충실도 실패 시 대안 |
| 전체 앱 UI 프레임워크 교체 | 현재 라이브러리까지 변경 범위 확대 | 이번 편집기 전제 조건으로 두지 않음 |

경로 Boolean 연산은 Paper.js를 **기하 연산 어댑터**로 평가한다. 두 라이브러리가 각각 문서와 Undo를 소유하게 만들지 않는다. Paper.js는 합치기·교집합·빼기·분할과 Bézier 경로를 지원한다. [공식 소스](https://github.com/paperjs/paper.js)

Fabric의 SVG 가져오기 지원이 모든 BioArt SVG의 무손실 변환을 보장하지는 않는다. 원본 SVG 배치는 정제된 원본을 유지하고, 경로 편집은 별도 변환 결과로 관리한다. 클립·마스크·그라디언트·텍스트·그룹 구조의 충실도를 실제 자료로 검증한다.

새 TypeScript 제작실은 Bun으로 로컬 번들링한다. 기존 개발 서버·패키징에 정적 번들 배포를 연결하고 typecheck 대상에 포함한다. 배포 앱이 CDN에 의존하지 않도록 한다. 버전과 라이선스는 0단계에서 고정한다.

### 6.2 정본 문서

`schemaVersion: 1`의 새 문서는 다음 정보를 갖는다. 아래는 필드 설계이며 확정된 API 명세는 아니다.

| 영역 | 주요 정보 |
| --- | --- |
| 문서 | documentId, projectId, schemaVersion, revision, 제목, 생성/수정 시각 |
| 아트보드 | id, 문서상 위치, 논리 크기, 물리 크기, 배경, 인쇄 설정 |
| 노드 | id, type, parentId, 자식 순서, transform, style, visible, locked |
| 유형별 데이터 | asset, image, shape, path, text, connector, group, generator, equation, table, inset |
| 자료 | content hash, 프로젝트 상대 경로 또는 catalog 참조, 원본 ID, 출처·라이선스 |
| 연결 | 대상 nodeId와 로컬 anchor, 경유점, 선/화살촉 스타일 |
| 생성기 | generatorId, generatorVersion, params, random seed, 파생 geometry 캐시 |
| 이력 | 트랜잭션 ID, 기준 revision, 사람/AI 구분, 복구 체크포인트 |

논리 좌표와 화면 확대율을 분리한다. 물리 크기와 DPI는 내보내기 변환에서 적용한다. 그룹은 로컬 좌표를 사용하고, 부모 변환을 합성해 hit-test·스냅·연결선 위치를 계산한다. 순환 그룹, 존재하지 않는 참조, 비정상 좌표를 검증한다.

기존의 “그림 밑 라벨”은 독립 텍스트 노드로 만들고 그림과 그룹화한다. 필요하면 라벨만 이동하거나 숨길 수 있어야 한다. 자산 중복 배치는 같은 원본 자료를 참조하되 각 노드 ID는 다르게 만든다.

### 6.3 공통 명령·저장·Undo

마우스·키보드·속성창·AI·MCP가 같은 명령을 호출한다. 주요 명령은 노드 생성/삭제/변환, 속성 변경, 순서 변경, 그룹화, 연결/해제, 경로 편집, 생성기 매개변수 변경이다.

- 드래그 중에는 메모리의 미리보기만 변경하고, 놓을 때 하나의 트랜잭션으로 확정한다. 포인터 취소는 확정 전 상태로 복원한다.
- Undo/Redo는 같은 문서 명령과 역연산을 사용한다. Undo도 새 revision으로 저장하고 revision을 과거 숫자로 되돌리지 않는다.
- 요청에는 `baseRevision`과 `operationId`를 포함한다. 충돌을 검출하고 재시도 중 중복 적용을 막는다.
- 기본 저장은 로컬 백엔드가 담당한다. 프로젝트 단위 잠금 아래 스냅샷과 적용 이력을 한 번의 원자적 상태 교체로 확정한다. 여러 파일을 따로 바꾸면서 성공으로 표시하지 않는다.
- 변경 후 약 0.5–1초의 묶음 저장과 포커스 이동 시 저장을 목표로 한다. 미확정 변경의 복구 저널을 별도로 유지한다. 재시작 시 마지막 서버 확정본과 비교해 복구하며, loopback 포트 변경에도 복구본을 찾을 수 있는 안정적인 저장 위치를 선택한다.
- 외장 볼륨 분리·권한 오류·용량 부족 시 독립적인 사용자 데이터 경로에 복구본을 남기는 방식을 검증한다. “저장됨”은 실제 저장 응답 뒤에만 표시한다.

### 6.4 기존 프로젝트 이전

1. 원본 파일을 보존하고 0.1/0.2 장면의 사본을 새 문서로 변환한다.
2. 제목, 그림, 라벨, 텍스트, 화살표를 현재 그려지는 순서대로 이전한다. 렌더러가 암묵적으로 만들던 workflow 화살표도 실제 노드로 변환한다.
3. 생성 PNG는 이미지 노드로 옮기고 AI 생성 표시·참고 자료 목록을 유지한다. 원래 배경·제목의 표시 순서까지 비교한다.
4. studio 프로젝트의 대화와 AI 결과 버전, 현재 선택 버전을 모두 연결한다. 새 Undo 이력과 기존 AI 결과 버전은 다른 개념으로 유지한다.
5. 이전 전후 렌더링을 비교하고, 실패하면 기존 문서를 그대로 열 수 있게 한다. 미래 버전 문서를 구버전 앱이 덮어쓰지 못하게 한다.

## 7. 기능별 구현 내용

### 7.1 자유 배치와 연결선

빈 문서, 자료 추가, 다중 선택, 범위 선택, 복사/붙여넣기, 복제, 삭제, 크기 핸들, 비율 유지, 회전/반전, 그룹, 레이어, 정렬, 간격 분배, 스냅·가이드·격자를 제공한다. 클립아트를 아트보드 바깥 작업 영역에 둘 수 있게 하고, 출력 영역 밖 요소는 내보내기 검사에서 알린다.

직선·곡선·직각 연결선에 시작/끝 화살촉, 억제선, 점선, 굵기, 라벨을 추가한다. 단순 선과 객체에 붙는 연결선을 구분하고, 연결된 객체를 회전·그룹 이동해도 접점이 따라가게 한다. 삭제 시 연결선도 삭제할지 자유 끝점으로 남길지 명시적인 규칙을 둔다.

해부학적 방향 보존을 이유로 모든 회전을 막는 현재 규칙은 제거한다. 회전·반전은 허용하되 출처와 변형 기록을 보존하고, 수동 방향 잠금 기능을 제공한다. PNG의 반전과 과학적 좌우 해석을 자동으로 동일시하지 않는다.

### 7.2 벡터 드로잉과 원본 수정

- 사각형·타원·둥근 사각형·다각형·별·괄호, 선·호·자유곡선.
- 펜의 점 생성, 닫기, 앵커 추가/삭제, 곡선 핸들, smooth/corner 전환.
- 자유곡선 단순화, 경로 합치기/빼기/교집합/분할, clipping mask.
- 단색/그라디언트, 선 끝·연결 형태, 투명도, 스타일 복사, 스포이트.
- SVG “편집용 복사본”: 경로·그룹 단위 선택, 색 변경, 일부 삭제, 부분 추출. 원본 파일에 쓰지 않는다.
- 복잡한 warp·blend·offset은 기본 경로 편집 후 하위 단계로 구현한다. 모든 SVG 효과의 완전 편집을 첫 릴리스 조건으로 잡지 않는다.
- PNG는 자르기·마스크·외형 변환이 가능하지만 내부 경로 편집은 제공하지 않는다. 벡터화는 별도의 추정 변환으로 나중에 평가한다.

### 7.3 과학 객체와 브러시

첫 묶음은 세포막, 소포/리포좀, 일반 세포와 핵, 수용체, 항체, DNA/RNA 도식, 입자 군집, 하이드로젤, 구획/장벽, 실험 튜브를 후보로 한다. 실제 사용 빈도와 검증 가능한 구조부터 8–12개 생성기로 좁혀 출하한다.

브러시는 막 이중층, 비드/분자 사슬, DNA/RNA 도식, 섬유/필라멘트 등을 곡선에 배치한다. 경로 길이에 따른 배치 간격, 곡률, 방향, 간격 겹침을 처리한다. 색·두께·반복 수·밀도·구성요소를 매개변수로 제공한다.

생성기는 코드 실행 문자열을 받지 않는다. 허용된 ID와 검증된 매개변수만 받아 결정적으로 geometry를 만든다. seed와 버전을 저장하고, 생성기 업데이트가 과거 문서의 외형을 자동 변경하지 않게 한다. 사용자가 원할 때 경로로 펼치되 생성기 원본 사본을 보관한다.

이 객체들은 원칙적으로 **개념 설명용 도식**이다. 실제 분자 구조나 물리 축척을 표현한다고 표시하려면 별도의 데이터와 검증이 필요하다.

### 7.4 논문 도해 기능

패널 A/B/C 자동 라벨, 그리드, 반복 여백, 확대 삽화, 범례, 공통 색상·서체 스타일, 템플릿을 제공한다. 확대 삽화는 원본 노드·영역을 참조하고 실시간/고정 상태를 구분한다. 자기 자신을 확대하는 순환 참조는 거부한다.

수식은 LaTeX 원문과 렌더링 결과를 함께 저장한다. 표는 셀 데이터·행/열·스타일을 보존한다. 물리 스케일바는 사용자가 보정값과 단위를 입력한 자료에만 실측 의미를 부여한다. 교정 정보가 없는 클립아트에는 정확한 μm 스케일을 추정해 붙이지 않는다.

### 7.5 내보내기와 재현성

- 편집용 SVG, 벡터 PDF, PNG, TIFF를 우선한다. JPEG/WebP는 편의 출력으로 추가한다.
- 문서 크기와 mm/in/px, 300/600/1200 dpi 또는 직접 입력을 지원한다. 인쇄 프리셋은 편집 가능하게 하고 특정 저널 최신 규정으로 고정하지 않는다.
- SVG/PDF에서 가능한 요소는 벡터로 유지한다. 래스터 이미지와 지원하지 않는 효과는 범위를 표시하고 필요한 부분만 rasterize한다.
- SVG의 원본 배치는 격리된 SVG 자산을 유지할 수 있다. 외부 편집기에서 경로 편집이 필요한 출력은 ID 충돌을 해결한 인라인 SVG를 별도 검증한다.
- 텍스트 편집 유지와 윤곽선 변환을 구분한다. 폰트 누락·대체, 한국어·그리스 문자·위첨자·아래첨자의 차이를 검사한다. SVG와 PDF의 폰트 포함 가능성은 각각 검증한다.
- 프리플라이트: 누락 자료, 출력 밖 요소, 래스터의 실제 유효 DPI, 투명도, 작은 글씨/가는 선, 저작자·라이선스 누락을 검사한다.
- `pixelWidth = round(widthMm / 25.4 × dpi)`로 출력 픽셀 수를 계산하고 PNG/TIFF의 해상도 메타데이터도 확인한다. 출력 DPI 지정만으로 저해상도 입력이 선명해졌다고 표시하지 않는다.
- 내보내기 job은 특정 revision의 불변 스냅샷을 사용한다. 편집을 이어가도 결과가 섞이지 않아야 한다. 대형 TIFF/PDF에는 진행·취소·메모리 한도와 타일 렌더링을 검토한다.
- 휴대용 프로젝트 ZIP은 문서·필요한 자료·파생본·출처·생성기 정보·미리보기를 포함한다. 기존 export ZIP과 구분해 가져오기까지 지원한다. 재배포가 허용되지 않는 자료는 누락 사유와 재연결 정보를 남긴다.
- SVG 정본 출력기를 중심에 두고 PNG는 기존 resvg 경로를 확장한다. PDF 변환기는 실제 SVG·폰트·마스크 보존 테스트 후 선정한다. 프런트엔드 화면과 백엔드 출력 간 차이를 회귀 검사한다.

### 7.6 AI와 MCP

기존 Codex 연결과 ImageGen을 유지한다. AI는 노드 ID와 허용된 명령을 사용하며, 선택 영역·잠금·현재 revision을 따른다. 매번 전체 장면을 새로 만드는 방식에서 부분 수정으로 전환한다.

AI 응답은 변경안으로 검증·미리보기한 다음 하나의 트랜잭션으로 적용한다. 한 응답을 한 번의 Undo로 되돌릴 수 있게 한다. 생성 도중 사용자가 편집했으면 최신 문서와 충돌을 검사하고, 오래된 결과가 사용자 변경을 덮어쓰지 못하게 한다. 전체 라이브러리 검색·자산 추천은 기존 검색 API를 통해 단계적으로 추가한다.

AI 이미지도 프로젝트의 일반 이미지 노드로 취급한다. 내부 픽셀을 벡터 레이어로 편집할 수 있다고 오인하게 만들지 않는다. 원본 자산·생성기·AI 이미지의 출처 유형을 분리한다.

MCP는 같은 명령의 제한된 로컬 인터페이스로 확장한다. 문서 조회, 선택 영역 조회, 노드 추가/수정, 생성기 설정, 내보내기를 지원하되 파일 시스템이나 임의 SVG/JavaScript 실행 권한을 주지 않는다. GUI와 MCP의 저장·revision 정책도 동일하게 한다.

## 8. 구현 단계와 완료 기준

아래는 한 명의 전담 개발자가 설계·구현·검증을 수행하는 경우의 초기 작업량 추정이다. 실제 달력 일정이나 완료 약속이 아니며, 0단계 후 재산정한다. 반복 QA와 코드 리뷰를 포함하되 미확인 엔진 문제는 범위를 늘릴 수 있다.

| --- | --- | --- | --- |
| 0. 기술 검증 | 엔진·출력 실험, SVG 표본, 문서 명세, 화면 초안 | 실제 WKWebView에서 대표 SVG·한글·클립·그룹 변환과 저장 왕복 통과; 엔진 결정 기록 | 1–2주 |
| 1. 편집 기반 | 문서 v1, 이전, 직접 렌더링, 빈 문서, 자료 CRUD, 선택/변환, 레이어/그룹, Undo, 저장 복구 | AI 없이 20개 이상 자산으로 도해 제작→종료→재시작→동일 문서 복구 | 3–4주 |
| 2. 자유 드로잉 | 도형·펜·경로·마스크·색, 스냅, 연결선, SVG 복사본 편집 | 세포 신호전달 도해를 직접 완성; 그룹 이동 후 연결 유지, Undo 왕복 일치 | 3–4주 |
| 3. 과학 제작 | 생성기·브러시·확대 삽화·수식·표·패널 템플릿 | 대표 5개 과학 도해, 모든 생성 요소 재편집·재열기 가능 | 4–6주 |
| 4. 출판·휴대성 | 물리 크기, PDF/TIFF, 폰트, 프리플라이트, 프로젝트 가져오기 | 174 mm/600 dpi 출력 검사, 별도 작업 폴더에서 가져오기·재편집 성공 | 3–5주 |
| 5. AI 명령화 | 선택 기반 편집, 충돌 처리, AI Undo, MCP | 지정 노드만 수정, 변경 미리보기, 실패 복구, GUI/MCP 결과 일치 | 2–3주 |

핵심 편집기 0–5단계 합계는 약 **16–24 작업주**로 잡는다. 첫 실용 버전은 0–2단계(약 7–10 작업주)로 정의한다. 기존 AI 생성은 이 기간에도 호환 어댑터로 유지하며, AI 작업 동안의 편집 잠금은 5단계에서 충돌 처리로 대체할 수 있다.

각 단계는 독립적으로 사용 가능한 상태로 출시한다. 3D나 통계 기능의 완료를 기다려 기본 편집기 출하를 늦추지 않는다.

## 9. 전체 기능에 접근하기 위한 후속 확장

| 확장 | 실제 제공할 작업 | 선행 조건 | 별도 추정 |
| --- | --- | --- | --- |
| A. 슬라이드·포스터 | 문서 요소 재사용, 슬라이드 정렬·발표·노트·PDF; 열 기반 포스터·텍스트 재배치·인쇄 크기 | 문서·텍스트·다중 아트보드·PDF | 4–8 작업주 |
| B. 분자·단백질 | PDB/mmCIF 입력, 잔기·사슬 선택, 표면/리본/볼앤스틱; 분자·반응 편집, PubChem 입력 | 외부 자료 캐시·삽입물 상태 저장 | 6–10 작업주 |
| C. 3D Studio | 장면·모델·카메라·재질·조명, 기본 과학 생성기, 투명 렌더; 이후 고급 렌더·포맷 확대 | WebGL 검증·비동기 job·재편집 삽입물 | 8–14 작업주 |
| D. 그래프·통계 | CSV/표 입력→그래프, 변경 연결; 이후 가정·방법·결과가 명시된 통계 | 데이터 노드·출력·수치 검증 fixtures | 6–12 작업주 |
| E. 광학·이미지 | 장비·튜브 도해 확대, 단계적 광선 모형; crop/levels/LUT/마스크와 수정 이력 | connector·이미지 파이프라인 | 6–12 작업주 |

이 추정은 각 모듈의 첫 실용 버전 기준으로, LabCanvas의 모든 세부 기능과 동등함을 보장하지 않는다. 전체 확장은 핵심 편집기 이후에도 여러 달 규모다. 구현 전 모듈별 상세 설계와 라이브러리·라이선스 검토가 필요하다.

분자/단백질/3D/그래프는 “삽입 가능한 별도 편집물”이라는 공통 계약을 사용한다. 원본 데이터, 표시 설정, 파생 이미지/벡터, 원본 편집물 ID를 저장하고, 더블클릭으로 다시 편집해 도해를 갱신한다. 삽입 시 납작한 이미지 한 장만 남기는 것을 최종 상태로 삼지 않는다.

통계 계산은 검증된 수치 라이브러리와 기준값을 대조한다. 광학 시뮬레이션은 지원하는 물리 모형·가정을 표시한다. 실험 이미지 보정은 원본과 처리 기록을 보존하고, 결과를 바꾸는 국소 수정에는 구분된 이력을 남긴다.

클라우드 동기화·실시간 공동 편집·계정·결제는 현재 로컬 앱의 도해 편집 요구와 분리된 후속 과제로 둔다. 로컬 문서의 revision과 자료 ID는 나중에 동기화할 수 있도록 설계하되, 초기부터 협업 서버를 만들지는 않는다.

## 11. 검증과 출시 조건

### 11.1 실물 도해 시나리오

1. **폐–폐포 가스 교환:** 원본 자산, 부분 확대, 교차 화살표, 라벨, 출처.
2. **세포 신호전달:** 막 브러시, 수용체, 억제선, 곡선 연결선, 그룹 이동.
3. **실험 워크플로:** 반복 자산, 실험 도구, 정렬·간격 분배, 튜브 연결.
4. **다중 패널 논문 그림:** A–F 패널, 표/수식, 한국어/영어/그리스 문자, 인쇄 크기.
5. **AI 이미지 혼합 도해:** 생성 PNG와 벡터 주석, 구분된 출처, 선택 영역 AI 수정과 Undo.

각 시나리오는 만들기→수정→저장→앱 종료→재시작→재편집→출력까지 수행한다. 개발 브라우저와 배포된 macOS 앱을 구분해 검증한다.

### 11.2 회귀·실패 검사

- 실제 BioArt SVG의 작은/큰 파일, 다중 그룹, clip/mask, gradient, style, 텍스트를 포함한 30–50개 표본을 선정한다. PNG와 생성 이미지도 포함한다.
- 다른 확대율에서 동일 포인터 좌표가 동일 문서 위치에 매핑되는지 확인한다. 회전된 중첩 그룹·다중 선택·클리핑 뒤 hit-test와 연결선을 검사한다.
- 편집 명령→Undo→Redo 후 문서·출력 일치, AI 일괄 Undo, 새 편집 후 Redo 무효화.
- 0.1/0.2 이전, 과거 AI 버전, 누락 자료, 손상 프로젝트, 미래 스키마, ZIP path traversal과 과도한 압축 해제 제한.
- 저장 중 종료, 동일 문서를 두 프로세스에서 수정, 외장 볼륨 분리, 중복 요청, stale AI 결과.
- 가져오기 SVG의 script/event/외부 URL·DTD·과도한 path를 제한한다. 기존 정제를 DOM/객체 삽입 전에 적용하고 ID namespace 충돌을 해결한다.
- export SVG/PDF를 외부 뷰어에서 열고, 벡터 유지·폰트·레이어 순서·마스크·투명도·물리 크기를 확인한다. TIFF/PNG의 픽셀 수와 DPI 필드를 직접 읽는다.
- 원본 BioArt 파일 체크섬이 편집·가져오기·내보내기 전후 동일한지 확인한다.

### 11.3 초기 성능 목표

기준 장비·OS·WKWebView 버전과 자료 복잡도를 0단계에서 기록한다. 노드 수뿐 아니라 SVG path 수·포인트 수·래스터 해상도를 함께 측정한다.

- 일반 도해 200개 노드에서 포인터 조작 프레임의 p95 33 ms 이하를 초기 목표로 한다.
- 1,000개 노드에서는 스트레스 검증을 수행하고, 화면 밖 객체 생략·복잡한 SVG 캐시·작업 분할 여부를 결정한다.
- 일반 문서의 완료된 조작이 1초 내 저장되는 것을 목표로 하되, 큰 자산 복사와 출력은 별도 작업으로 표시한다.
- 서버 미리보기 왕복이 매 포인터 이동에 끼어들지 않아야 한다.

## 13. 첫 구현 작업의 구체적 범위

착수 시 첫 작업은 **기존 프로젝트 하나를 새 캔버스에서 열고, 다중 선택·회전·그룹·Undo·저장·재열기까지 되는 작은 수직 구현**이다. 이때 실제 BioArt SVG로 원본 외형을 확인한다. 같은 문서를 SVG로 출력해 화면과 비교한 뒤 드로잉 도구를 늘린다.

첫 실용 릴리스에는 빈 캔버스, 제작실 내 BioArt 검색·추가, 직접 조작, 레이어·그룹, 정렬·스냅, 텍스트·도형·곡선·연결선, 기본 경로 편집, Undo/Redo, 자동 저장·복구, 기존 프로젝트 이전, SVG/PNG 출력이 들어간다. 이 범위를 충족하면 사용자가 말한 현재의 rudimentary한 편집 제약을 우선 해소할 수 있다.

## 4단계 출판 출력 구현 현황 (2026-10-14)

사용자가 요청한 PDF/TIFF, 물리 너비·DPI, 폰트 윤곽선/포함, 프리플라이트, 불변 revision 출력 작업을 구현했다. 실제 앱·출력 품질 검증은 [PHASE4_VALIDATION.md](PHASE4_VALIDATION.md)에 기록한다.

후속 작업으로 휴대용 프로젝트 ZIP 내보내기·가져오기를 구현해 4단계의 출판·휴대성 수용 기준을 충족했다. 설치 앱에서 기존 도해 2개를 ZIP으로 내보내고 원본 카탈로그가 없는 빈 작업 폴더로 가져와 수정·저장·앱 완전 종료·재열기·재내보내기 및 174 mm/600 DPI PDF·TIFF 출력을 검증했다. [휴대성 검증 기록](PORTABLE_VALIDATION.md).

계획의 미지원 자료 처리 방식은 구현에서 더 엄격하게 적용했다. 재배포 조건을 확인할 수 없는 자료를 빠뜨린 ZIP을 만들지 않고 이유를 표시해 내보내기를 중단한다. 폰트 바이너리는 동봉하지 않는다. mm/in/px 입력 단위 전환과 PDF/X·PDF/A·CMYK 인증은 남은 확장 범위다.
